1The Fertility Metric — Step-by-Step Explanation

This is the most important thing to understand. The same sentence, the same tokenizer, the same output tokens — but two completely different fertility numbers depending on what you put in the denominator.

Step 1 — What is a "whitespace word"? (Our method)

Simply split on spaces. Every space-separated chunk = 1 word. Punctuation sticks to the word next to it.

Our method: text.split()

Notice: "India," and "Asia." are each counted as 1 word.
The comma and period are invisible to our counter.

Correct method: faithful units

15faithful units
Rule: each letter-run = 1 unit. Each punctuation mark = its own unit.
The 2 commas + 1 period = 3 extra units the word counter missed.

Step 2 — Same tokenizer output, two different fertility numbers

Our tokenizer produces 13 tokens for this sentence. Watch what happens when we divide by the two different denominators:

Our metric (tokens ÷ words)

Sounds like 1 token ≈ 1 word — looks reasonable!

Correct metric (tokens ÷ faithful units)

13 tokens ÷ 15 faithful units = 0.867 fertility
Below 1.0 — tokenizer is actually efficient!

Why script sharing matters for a shared 10K vocabulary

With Tamil — the vocabulary must contain:

  • ~50 Tamil base characters (unique to Tamil)
  • ~50 Hindi/Devanagari base characters
  • ~52 English base characters
  • ~50 Telugu base characters
  • Merged subwords for all 4 scripts independently
Tamil and Hindi compete for the same merge budget in training. Tamil needs more dedicated merges.

With Maithili — the vocabulary gets:

  • Hindi and Maithili share Devanagari base chars
  • A merge like ▁भ + ारत serves both languages
  • Maithili effectively "borrows" Hindi's subwords for common words
  • More of the 10K budget goes to genuinely useful subwords
Shared script = more efficient use of vocabulary, lower fertility for both Maithili and Hindi.

Bottom line: Tamil is not "wrong" — it's a valid Indian language. But it is harder to balance in a shared vocabulary because of script isolation. The assignment solution chose Maithili specifically because its Devanagari script creates natural token sharing with Hindi, helping keep the fertility spread low (better score).

Question 4 What happens to punctuation — trace a sentence through manually before training

Before running BPE training, trace one sentence through the pre-tokenizer step by hand. Ask: where does punctuation go?

Input: "India, officially the Republic of India."
After text.split(): "India," "officially" "the" "Republic" "of" "India."
BPE sees: I-n-d-i-a-, as one unit → merges → "India," as one token
The comma is now part of the token. You can never split it back out.

This trace raises an immediate follow-up question: can I decode the tokens back to the original text? Try it:

encode("India, officially...") → ["India,", "officially", ...]
decode(["India,", "officially", ...]) → "India, officially..." ✓ (looks right!)
But now try: encode("India") + encode(",") separately...
decode(["India", ","]) → "India ," ✗ (space inserted — round-trip broken)
The round-trip problem only becomes visible when you try to encode part of the text or check character-level fidelity. The spec says "decode(encode(text)) must preserve every non-whitespace character." A 10-sentence round-trip test before training would have surfaced this immediately.
Question 5 Why does SentencePiece use Metaspace — what problem was it designed to solve?

Before writing a custom pre-tokenizer, spend 20 minutes reading why existing tokenizers (SentencePiece, HuggingFace tokenizers) made the design choices they did. You don't need to use their code — but understanding their reasoning tells you what problems your design needs to solve.

What you'd learn about whitespace pre-tokenization

  • Splits on whitespace → punctuation fuses to adjacent word
  • Different languages punctuate differently (Devanagari danda ।, full-stop, comma)
  • No way to reconstruct original spacing or punctuation placement
  • Used by early word-level models — not designed for subword BPE

What you'd learn about Metaspace (▁)

  • Replaces leading space with ▁ — encodes word boundary inside the token
  • Punctuation can now be its own token or merge naturally via BPE
  • Decoder just strips/restores ▁ → exact round-trip guaranteed
  • Designed specifically for multilingual, script-agnostic tokenization
Reading the SentencePiece paper (Kudo & Richardson, 2018) or the HuggingFace tokenizers docs for 30 minutes would have told you that Metaspace exists precisely to solve the punctuation-fusion and round-trip problems. You don't need to discover this from scratch — it's documented.

def compute_fertility(text, merges,
                      vocab_str2id, vocab_id2str):
    words = text.split()
    if not words:
        return 0, 0, 0.0
    tokens = tokenize(text, merges,

Solution code — train_tokenizer.py:31–35
import regex
FAITHFUL_UNIT_RE = regex.compile(
    r"[\p{L}\p{M}\p{N}]+|[^\s\p{L}\p{M}\p{N}]"
)

def faithful_units(text: str) -> int:
    return len(
        FAITHFUL_UNIT_RE.findall(text)
    )

ratios = {
    code: token_counts[code] / units[code]
    for code in LANGS
}
Each letter/number run = 1 unit; each visible punctuation char = 1 unit
The regex [\p{L}\p{M}\p{N}]+ matches any Unicode letter, mark, or number run. The alternation [^\s\p{L}\p{M}\p{N}] catches every non-whitespace, non-word character — i.e., each punctuation/symbol — as its own unit. Requires pip install regex for Unicode property support.

from tokenizers import Tokenizer
from tokenizers.models import BPE
from tokenizers.normalizers import NFKC
from tokenizers.pre_tokenizers import Metaspace
from tokenizers.decoders import (
    Metaspace as MetaspaceDecoder
)
from tokenizers.trainers import BpeTrainer

def make_tokenizer():
    tok = Tokenizer(BPE(unk_token="[UNK]"))
    tok.normalizer = NFKC()
    tok.pre_tokenizer = Metaspace(
        replacement="▁",
        prepend_scheme="never"
    )
    tok.decoder = MetaspaceDecoder(
        replacement="▁",
        prepend_scheme="never"
    )
    return tok
NFKC · Metaspace separates punct · decoder enables round-trip · 1 special token
What Metaspace does: Instead of text.split(), it replaces the leading space of each word with a ▁ character and lets BPE decide where to split — including between a word and trailing punctuation. This is what makes India, → India + , possible. Install with pip install tokenizers.
