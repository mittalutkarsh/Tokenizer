Decision-ready evidence + design brief · July 2026

40B India-first foundation model

8T pre-training tokens · 256K two-stage tokenizer · 25% India/Indic · 20% code. The assignment’s benchmark target is Gemma 3 4B, the 4B checkpoint listed by Ollama—not “Gemma version 4.” A separate Gemma 4 family now exists, so the exact checkpoint must be frozen in the eval manifest. [2] [3] [4]

Anchor reconciliation

Token budget

70B parameters / ≈1.4T tokens gives the familiar ≈20 tokens/parameter Chinchilla shorthand; the paper’s core result is that model size and tokens should scale together under fixed compute. [1]

4T / 12T / 14T are Gemma 3’s published budgets for 4B / 12B / 27B. The 4B run used ≈1,000 tokens/parameter, proving that 800B is only a compute-optimal floor. [2]

DESIGN 8T is a capability/serving-economics compromise: roughly 1.92×10²⁴ FLOPs under the rough 6ND estimate.

Capability bar

43.6 MMLU-Pro, 12.6 LiveCodeBench, 36.3 BIRD-SQL, 30.8 GPQA Diamond, 75.6 MATH, 54.5 Global-MMLU-Lite are published Gemma 3 4B-IT anchors. [2]

No published per-language Indic scorecard was found. Aggregate multilingual scores cannot establish Hindi/Telugu/Odia quality; run the frozen Gemma checkpoint in the same harness across all ten languages.

Vocabulary decision

256K two-stage BPE DESIGN

  • 90% script-aware subword; 10% frequent cross-word units
  • 256 byte-fallback tokens; whitespace/indentation preservation; individual digits; explicit tool tokens
  • Joint temperature sampling with script/domain soft quotas
  • 99% of learned tokens must have ≥100K expected occurrences; no non-control token below 10K
  • Ship 256K only if it saves ≥5% weighted sequence length versus 200K

2.10B tied embedding parameters ASSUME d_model=8192

  • 256,000 × 8,192 = 2.097B = 5.24% of 40B
  • BF16 embedding weights = 3.91 GiB
  • Versus 128K: +1.05B parameters
  • Untied embeddings = 4.19B parameters (10.5%): reject
